# Interlacing 功能分支实施计划

## 本轮选择与验收

| 能力 | 已交付的范围 | 如何复验 |
|---|---|---|
| 从中间结论另试一条路线 | 在持久化根图的稳定位置，修改指定节点的一条已提交输出。分叉记录父运行、位置、输出版本和理由。 | 同一报价分出两条路线，独立工作保留；数据库里的已签审核保留在父运行，新报价在新运行单独送审。 |
| 实时查看进度 | 主管通过一个 HTTP 连接订阅根运行，观察节点事件、业务进度和状态。用最后的事件序号续读。 | 阻塞慢节点，先收到进度再放行；两个观察者分别连接，断开后能按序续读。普通成员访问同一接口会被拒绝。 |
| 故障分类与有限重试 | 同步函数可选择连接故障、超时或两者。主管明确重试时，已耗尽的激活获得新一轮预算。 | 在第一次失败记账后杀掉进程，接管后总调用仍为两次；随后模拟服务恢复并核对实际调用计数。 |

人工审核继续使用图上的显式节点，保留分派、认领、转派和答复版本。资料沿用现有名称、版本和文本过滤。函数中途补问与语义检索均已移出实施队列。接口和示例见[协作服务手册](POSTGRES.md)。

## 审查补出的前置工作与后续项目

| 优先级 | 项目和理由 | 单独验收的条件 |
|---|---|---|
| 已完成 | **任务归属（A1）**。显式路径由服务预检，需要展开的路径由工作进程在执行前复核。[接口与动态节点边界](POSTGRES.md) | 错别字、无对应人工节点的路径有确定结果；合法指定任务对主管和指定成员可见，其他普通成员无法认领；显式开放的任务仍可竞争认领。 |
| 已完成 | **创建请求去重（A3）**。为创建运行增加可选请求键。 | 模拟创建已提交但响应丢失；带同一请求键重发只创建一次，有意的第二次运行可使用新键。 |
| 已完成 | **嵌套并行与可恢复的质疑/答复**。这是 Interlacing 自身的表达能力。新运行的根图和嵌套块共享并发名额。持久化质疑与答复已接入 SQLite 和 PostgreSQL。 | 验证共享预算、排队和取消。用“三组同时审稿、各组内两位专家”的图测试。在质疑已提交、答复前退出进程，恢复后质疑仍指向原版本，其他组可前进。 |
| 对外演示前 | **拆开调度对照脚本中的两项观察**。原脚本要求观察者先收到更新才释放慢节点，在固定版本下仍会偶发超时。 | 让慢节点有独立结束条件，分别记录观察者收到更新和下游开始消费的时间。重复运行并报告各顺序出现次数；只对框架承诺的行为做断言。 |
| 部署前 | **容量、备份恢复与长历史成本**。本轮已有单机停写恢复证据；分叉仍需读取并复制源历史前缀。 | 固定数据量与持久化保证，记录首个可用结果、P95 等待和不同历史长度的分叉耗时与存储量。做双主机接管及持续写入备份演练，记录实际恢复时长、恢复点与文件完整性。 |
| 按需求 | **本地内容目录、跨语言客户端与浏览器工作台**。本地 artifact 入口见审查 A4；其他两项取决于实际使用者。 | 本地目录可在新进程恢复内容引用；非 Python 客户端能完成认领与答复；审核人能从浏览器定位一次过期任务的原因。三个交付独立排期。 |

多人返工示例、可按版本提交答复的审核页面及使用步骤见[协作手册](POSTGRES.md)。

涉及调度、恢复或图协议的后续改动，要分别给出原标准模式和新增持久化模式的验收结果。保留一份由基线版本产生的运行目录，验证新版本可以接着处理；公开导出和日志格式的增量变化单列。多人服务尚未覆盖的协议继续标明支持范围。[本次兼容性复核](BRANCH_REVIEW.md)
