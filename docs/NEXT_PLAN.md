# Interlacing 下一轮实施计划

**状态：候选方案，待逐项确认。** 起点是功能分支 `5c3c5a8`。目标是让一张真实的多人协作图，从本地实验迁到服务器后，仍能并行工作、说明每个结论的来源，并在进程故障后继续运行。用用户能完成的任务验收，每项可单独提交、检查和回退。[分支审查与实测边界](BRANCH_REVIEW.md)

## 五项用户能力

以下编号沿用讨论顺序。实施优先级另列在表后。

| 项目 | 要交付的行为 | 关键设计与依赖 | 首版验收 |
|---|---|---|---|
| 1　函数执行中临时问人 | 普通业务函数发现材料不全时能向指定成员补问。同一次业务处理可以连续提两个不同问题。 | 在激活、轮次和问题标识之间建立稳定关系，复用 HumanNode 的认领、版本校验、答复事务和过期机制。写明恢复时哪些代码会重新进入、哪些外部操作由业务幂等键保护。依赖下文的任务归属修复。 | 触发条件为假时零待办；为真时只向指定成员提问。两次提问之间退出进程，恢复后第一次答案继续有效。修改原输入后，旧待办拒收，另一支路仍能运行。 |
| 2　从中间业务结论创建分叉 | 主管从一版已提交的风险结论派生另一条路线，保留未受影响工作与原结论。 | 首版只允许修改可定位、带类型的已提交输出。记录来源位置、旧值版本、操作者和修改理由。沿用消息读取关系确定返工范围。先使用没有未完成激活的位置；正在执行的节点和外部副作用需要另定语义。 | 同一点生成两条不同结论的分叉。验证模式拒绝错误类型；原历史、已确认的原审核不变；新分叉只重算实际依赖者。中断重启后能解释结果来自哪次修改。 |
| 3　远程流式输出与业务进度 | 客户端可以同时看模型增量输出、节点事件和自定义进度，断线后知道能从哪里继续。 | 先定义事件类型、作用域、序号和权限，再选服务传输方式。区分持久化业务事件与可丢弃的显示增量，明确游标、慢客户端和保留期。现有分页历史仍可使用。 | 两个订阅者观察同一运行，中途断开一个。重连后已承诺保留的事件可按序续读；过期游标有明确反馈；慢客户端不阻塞调度；私有内容只送达有权的成员。 |
| 4　可配置的节点失败处理 | 开发者可区分暂时不可用、输入错误和需要人工干预，并给同步、异步节点选择合适处理方式。 | 先明确自动尝试、崩溃接管和人工重新尝试的边界，再增加异常分类、退避、耗尽后的处理。已经发出部分结果的节点要给出可验证的重放规则。 | 暂时故障达到预算后停止；永久错误直接报告；退避中断保留剩余次数；主管授权新尝试后能够成功。异步取消及时生效，已发布的结果及外部业务键可以追溯。 |
| 5　按语义找回历史资料 | 搜“供应商延期”能找到描述“交货日期顺延两周”的授权材料，并返回命中的具体版本。 | 保留名称和版本精确检索，抽象可替换的索引和嵌入提供方。查询、取回、更新、删除都遵守原项目与个人权限。文件先定可索引格式，再扩展正文提取。 | 建一组含改写、无关材料和多个历史版本的样本，与现有子串搜索比较命中率及延迟。私有资料隔离、索引重建和旧版来源定位分别验收；索引不可用时精确检索可继续。 |

## 审查补出的前置工作与后续项目

| 优先级 | 项目和理由 | 单独验收的条件 |
|---|---|---|
| 先做 | **任务归属**。审查 A1 会改变谁能看到并认领任务。先校验静态和嵌套分派路径，再定义动态节点的开放策略。 | 错别字、无对应人工节点的路径有确定结果；合法指定任务对主管和指定成员可见，其他普通成员无法认领；显式开放的任务仍可竞争认领。 |
| 接着做 | **重试意图与创建请求去重**。A2 先并入第 4 项的第一步，A3 单独做成兼容性 API 变更。 | 故障恢复不增加自动预算，人工重试有新审计记录。模拟创建已提交但响应丢失；带同一请求键重发只创建一次，有意的第二次运行可使用新键。 |
| 内核优先 | **嵌套并行与可恢复的质疑/答复**。这是 Interlacing 自身的表达能力。当前服务的顶层并行已验收，嵌套块和持久化质疑仍有限制。 | 先做跨层工作线程预算、公平调度与取消，再做质疑的持久身份和答复归属。用“三组同时审稿、各组内两位专家”的图测试。在质疑已提交、答复前退出进程，恢复后质疑仍指向原版本，其他组可前进。 |
| 对外演示前 | **拆开调度对照脚本中的两项观察**。原脚本要求观察者先收到更新才释放慢节点，在固定版本下仍会偶发超时。 | 让慢节点有独立结束条件，分别记录观察者收到更新和下游开始消费的时间。重复运行并报告各顺序出现次数；只对框架承诺的行为做断言。 |
| 部署前 | **容量、备份恢复与长历史成本**。本轮已有单机停写恢复证据；分叉仍需读取并复制源历史前缀。 | 固定数据量与持久化保证，记录首个可用结果、P95 等待和不同历史长度的分叉耗时与存储量。做双主机接管及持续写入备份演练，记录实际恢复时长、恢复点与文件完整性。 |
| 按需求 | **本地内容目录、跨语言客户端与浏览器工作台**。本地 artifact 入口见审查 A4；其他两项取决于实际使用者。 | 本地目录可在新进程恢复内容引用；非 Python 客户端能完成认领与答复；审核人能从浏览器定位一次过期任务的原因。三个交付独立排期。 |

建议先处理 A1，再处理 A2、A3；随后以嵌套并行和质疑恢复为内核主线，依次接入函数中提问、中间结论分叉、事件订阅。第 4 项的异步与部分输出重试在明确重放语义后展开，第 5 项在取得真实检索样本后排期。每项开工前列变更面、兼容性和故障点；完成时记录实际复现命令、结果和剩余限制，并在功能分支提交。
