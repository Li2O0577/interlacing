# 持久化与协作分支审查

审查日期为 2026-11-26。审查对象是 `codex/journal-backend` 的 [5c3c5a8](https://github.com/Li2O0577/interlacing/commit/5c3c5a81a6fdf6a6919ed12714e342f8646290a9)。相对当时的 `main@8e73921`，受审范围为 10 次提交、48 个变更文件。本次审查覆盖日志接口、JSONL 兼容性、SQLite 检查点与局部返工、PostgreSQL 租约与事务、运行分叉、人工任务、资料权限及 Python、CLI、MCP 和 HTTP 入口。

**结论。** 受测版本的并行审核、进程接管、输入修订与独立分叉均通过回归。额外场景发现两处可能违背操作者意图的行为，以及一个影响网络重试的接口缺口。建议先解决任务归属，再扩大多人试用范围。以下结果对应上述提交，修复与新能力在[未来实施计划](NEXT_PLAN.md)中排期。

## 原审查发现

A1 的修复结果及本地模式的兼容性实测见下方的后续复核。下表保留修复前的复现条件。

| 发现 | 如何观察及实际结果 | 影响、可用做法与验收条件 |
|---|---|---|
| A1　分派路径写错时，任务会开放认领。优先处理 | 建一张只有一个 `HumanNode` 的图，指定现有成员 Alice，分派键与真实节点名相差一个字母。服务返回运行编号，工作进程进入等待。主管在任务列表看到 `state=open`、`assignee=null`。提交端核对了成员名，开任务时按节点路径查字典。 | 指定审核可能变为项目内公开待办。当前要核对实际任务归属。修复应让可静态解析的错误在提交时返回路径；动态节点须有明确的开放策略；合法的开抢任务继续可用。[启动与分派](../src/interlacing/collab/service.py) · [开任务](../src/interlacing/collab/worker.py) |
| A2　自动尝试耗尽后，人工重试可能没有发出新调用。优先澄清并修复 | 同步函数设置 `retry_attempts=2`，用临时开关模拟业务服务离线。两次调用均失败。恢复业务服务后，主管调用 `retry`，工作进程再次报告失败，外部调用计数仍为 2。 | 进程接管需要继承尝试次数，主管主动发起新的尝试则需要独立语义。目前可从失败绑定前的安全位置另开可执行分叉，先确认外部副作用。验收需同时覆盖接管、人工授权的新尝试、重复点击和审计。[函数尝试](../src/interlacing/nodes/function.py) · [运行重试](../src/interlacing/collab/service.py) |
| A3　创建运行缺少请求去重。接口缺口 | 对同一张普通图连续发送两次完全相同的 `start`。返回两个不同 UUID，两个运行都被工作进程执行。这样可以有意重复运行，但调用方没有键可表达“这是上次请求的重发”。 | 响应丢失后盲目重发可能重复启动业务。收到 UUID 后应持久保存。建议对创建操作支持项目范围内的可选请求键；同键同内容返回原结果，同键异内容报告冲突。人工答复的现有事务去重继续沿用。[服务操作](../src/interlacing/collab/service.py) |
| A4　本地 SQLite 的内容引用取决于启动入口。文档已澄清 | 含 `artifact` 边的测试图经默认本地 `Run.create(..., journal="sqlite", durable=True)` 在编译时报告未知协议。引擎测试显式使用 `standard(DirectoryStore(...))` 后可投递并恢复。 | 手册现已区分本地运行目录、显式配置 store 的 Python 引擎和 PostgreSQL 工作进程。后续可给本地运行目录增加持久内容目录配置。[本地入口](../src/interlacing/runs.py) · [引擎验收](../tests/test_durable.py) |

## 与 main 的兼容性及 A1 修复复核

以 `main@8e73921` 的原始测试、手册和示例作为独立基线。测试在单台 Linux、CPython 3.12.14 上运行，功能分支沿用 JSONL 作为本地运行目录的默认值，核心安装依赖仍为空。在新旧包分别加载后逐项核对了原公开名及其类上可访问的公共属性；可检查签名的原参数顺序、种类和默认值均保留。PostgreSQL 协作由单独的服务入口启用。

| 实测 | 结果及兼容边界 |
|---|---|
| 原始回归 | 将功能分支以 editable 方式安装，在独立的主线检出目录中运行原封不动的 `python -m pytest -q -rs tests`，确认导入路径指向功能分支。同一套件在主线原包上 527 项全过；换成功能分支后 525 项通过，2 项精确匹配断言失败。旧手册列举的 68 个公开名全部可用，增加了 `SQLiteJournal`。旧 JSONL 测试对改图事件的整条字典做相等比较，新行多出 `schema_version: 1`；改图后的输出及节点轮次断言均通过。严格枚举字段的外部日志读取器需要适配。 |
| 老用户实际用法 | 在仅安装分支 wheel 的干净环境跑主线自带的安装包冒烟脚本及 20 个原示例，覆盖本地并行、质疑和更正、运行中改图、招募、远程节点、CLI 和 MCP。把旧手册的公开名相等断言单独改为子集判断后，其余原始示例与断言通过。 |
| 跨版本恢复 | 主线进程运行准备节点后，在人工审核处等待，留下默认 JSONL 运行目录。关闭进程，用分支的 `Run` 读取同一待办、答复并恢复。结果为 `accepted`，准备节点和审核各完成一次。 |
| 模式差异 | 本地标准模式保留流式边、调用边、质疑与答复、激活中途收消息以及换图恢复。强持久化仅支持普通值和内容引用投递，限制激活中途收消息及换图恢复。PostgreSQL 服务支持顶层图并行，嵌套块内仍按串行配置执行。迁移时需要按图检查使用的协议与并发。 |

A1 的改动限于 PostgreSQL 协作入口。新提交的显式节点路径在入队前校验；依赖编译展开的节点在工作进程首次加载图时校验。检查在执行和开放待办之前完成。原有指定认领、开放认领及恢复已有待办的流程分别保留。提交仍可只分派部分任务，省略的路径和外层轮次继续开放。尚未由运行中改图产生的路径不能预分派。[接口和路径写法](POSTGRES.md) · [分派回归用例](../tests/test_postgres_collab.py)

修复后的功能分支全量回归为 587 项通过、0 跳过，含 17 项真实 PostgreSQL 集成测试。pyflakes 与 mypy（75 个源文件）通过，sdist 和 wheel 构建成功。以上兼容性记录针对受测平台、示例和恢复场景。

## SQL 质疑边交付与复核

本次在 `377a31a` 基线上扩展同一套持久化内核。SQLite 和 PostgreSQL 复用作用域内的提问、答复、次数预算与恢复状态；SQL 服务沿用现有事件、检查点、租约及人工待办表。更正事件同时记录新投递与对原问题的答复。已完成双方都不再需要回放的裁决会从检查点的质疑记录中移除，历史事件保留。

| 验收 | 实际观察 |
|---|---|
| 相同工作流对照 | 同一份图描述分别用标准引擎和 PostgreSQL 多人服务运行。两位审核者质疑同一笔 100 元的报价，一位得到“含税”的解释，另一位收到 113 元的新价。已读旧价的小计执行两次并得到 226；接收更正的审核和独立审核各执行一次。输出及各节点执行轮次一致。 |
| SQLite 断点 | 对普通值和内容引用分别测试。独立进程在问题写入、答复节点绑定、更正提交或解释写入时强制退出；新进程从检查点与日志继续。每条场景只有一次质疑及一次对应裁决。另验收二进制制品、同值更正、协程答复、次数耗尽及其他消费者的局部返工。 |
| PostgreSQL 接管与任务隔离 | 真实工作进程在质疑或更正写入后退出。测试使租约过期，验证旧代写入被拒，另一进程接手完成。两位成员分别完成分给自己的任务。另一个用例要求独立人工审核在质疑仍未答复时先行完成。两个嵌套块中的同名边各有自己的额度，子日志归档后仍能查到对应问题及答复编号。 |
