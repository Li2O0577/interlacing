# 持久化与协作分支审查

审查日期为 2026-11-26。审查对象是 `codex/journal-backend` 的 [5c3c5a8](https://github.com/Li2O0577/interlacing/commit/5c3c5a81a6fdf6a6919ed12714e342f8646290a9)。相对当时的 `main@8e73921`，受审范围为 10 次提交、48 个变更文件。本次审查覆盖日志接口、JSONL 兼容性、SQLite 检查点与局部返工、PostgreSQL 租约与事务、运行分叉、人工任务、资料权限及 Python、CLI、MCP 和 HTTP 入口。

**结论。** 受测版本的并行审核、进程接管、输入修订与独立分叉均通过回归。额外场景发现两处可能违背操作者意图的行为，以及一个影响网络重试的接口缺口。建议先解决任务归属，再扩大多人试用范围。以下结果对应上述提交，修复与新能力在[未来实施计划](NEXT_PLAN.md)中排期。

## 需要处理的发现

| 发现 | 如何观察及实际结果 | 影响、可用做法与验收条件 |
|---|---|---|
| A1　分派路径写错时，任务会开放认领。优先处理 | 建一张只有一个 `HumanNode` 的图，指定现有成员 Alice，分派键与真实节点名相差一个字母。服务返回运行编号，工作进程进入等待。主管在任务列表看到 `state=open`、`assignee=null`。提交端核对了成员名，开任务时按节点路径查字典。 | 指定审核可能变为项目内公开待办。当前要核对实际任务归属。修复应让可静态解析的错误在提交时返回路径；动态节点须有明确的开放策略；合法的开抢任务继续可用。[启动与分派](../src/interlacing/collab/service.py) · [开任务](../src/interlacing/collab/worker.py) |
| A2　自动尝试耗尽后，人工重试可能没有发出新调用。优先澄清并修复 | 同步函数设置 `retry_attempts=2`，用临时开关模拟业务服务离线。两次调用均失败。恢复业务服务后，主管调用 `retry`，工作进程再次报告失败，外部调用计数仍为 2。 | 进程接管需要继承尝试次数，主管主动发起新的尝试则需要独立语义。目前可从失败绑定前的安全位置另开可执行分叉，先确认外部副作用。验收需同时覆盖接管、人工授权的新尝试、重复点击和审计。[函数尝试](../src/interlacing/nodes/function.py) · [运行重试](../src/interlacing/collab/service.py) |
| A3　创建运行缺少请求去重。接口缺口 | 对同一张普通图连续发送两次完全相同的 `start`。返回两个不同 UUID，两个运行都被工作进程执行。这样可以有意重复运行，但调用方没有键可表达“这是上次请求的重发”。 | 响应丢失后盲目重发可能重复启动业务。收到 UUID 后应持久保存。建议对创建操作支持项目范围内的可选请求键；同键同内容返回原结果，同键异内容报告冲突。人工答复的现有事务去重继续沿用。[服务操作](../src/interlacing/collab/service.py) |
| A4　本地 SQLite 的内容引用取决于启动入口。文档已澄清 | 含 `artifact` 边的测试图经默认本地 `Run.create(..., journal="sqlite", durable=True)` 在编译时报告未知协议。引擎测试显式使用 `standard(DirectoryStore(...))` 后可投递并恢复。 | 手册现已区分本地运行目录、显式配置 store 的 Python 引擎和 PostgreSQL 工作进程。后续可给本地运行目录增加持久内容目录配置。[本地入口](../src/interlacing/runs.py) · [引擎验收](../tests/test_durable.py) |

## 实际执行的检查

| 范围 | 环境及结果 |
|---|---|
| 全量回归 | 同一提交在 Linux 上分别使用 CPython 3.11.18、3.12.14、3.13.5。每次各建临时 PostgreSQL 16.2 实例，安装 MCP 参考客户端与 psycopg。三次分别 **585 项通过、0 跳过**，其中每次含 15 项 PostgreSQL 集成测试。 |
| 恢复与一致性 | 套件覆盖 JSONL 中断、SQLite 迁移与检查点尾部重放、修订后定向返工、已提交答复与续跑命令的事务回滚、失效租约拒写、嵌套任务归档以及跨项目读取限制。另重复执行慢支路中的人工答复、旧租约、输入修订、同点双分叉四项组合场景，各跑五次，20 次均通过。 |
| 静态与交付 | `pyflakes src tests scripts examples` 通过。项目配置的 mypy 检查 75 个源文件通过，未标注类型的函数体仍受默认检查范围限制。分支相对主线的 `git diff --check` 通过。构建 sdist 及 wheel；干净环境只装 wheel 后通过 20 个示例、CLI 与 MCP 冒烟检查；另一环境安装 postgres 可选依赖，两次初始化均成功。 |
| 停写后的联合恢复 | 保存一份共享文件，并让一个人工任务停在等待状态。停止写入，用 `pg_dump -Fc` 备份，复制内容目录，`pg_restore --exit-on-error` 恢复到独立数据库。服务改用恢复库和目录后，文件字节与原文一致，原待办可被认领、提交并继续到完成。 |

另行复跑仓库的 LangGraph 对照脚本（LangGraph 1.2.24、SQLite 检查点扩展 3.1.3）。重试与中断恢复四次均通过；调度对照两次通过，两次在等待观察者释放慢节点时超时。将慢节点改为独立结束，另跑五次：下游五次均在慢节点结束后启动，观察者仅一次提前看到快节点更新。原脚本把观察时间当成了放行条件。学术展示可以使用已验证的下游启动顺序，不能把观察者提前收到更新描述为保证。[对照脚本与原始命令](LANGGRAPH_COMPARISON.md#复现命令)

本轮运行环境是单台 Linux 主机。跨机器接管、持续写入期间的备份、规模与延迟目标、macOS 和 Windows 的托管 CI 结果，以及真实模型或设备，均在本次实测范围之外。单机停写演练不能给出生产恢复时长或可容忍的数据丢失量。

## 如何复核

在仓库根目录按[检测命令](LANGGRAPH_COMPARISON.md#复现命令)使用专用临时数据库，运行 `python -m pytest -q -rs tests`。若出现 PostgreSQL 或 MCP 用例跳过，应先检查 DSN 和依赖。审查 A1 至 A3 可通过[主管和工作进程的公开操作](POSTGRES.md)按表中步骤复核；判断 A2 时同时读取运行状态并计数实际业务调用。
